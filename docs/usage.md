# 运行与使用指南

面向操作者：如何安装、配置、启动本服务，以及出问题怎么查。
产品与架构说明见 [DESIGN.md](../DESIGN.md)，实现细节见 [impl-notes/](impl-notes/index.md)。

## 环境要求

- Windows（当前唯一验证过的平台）
- Node.js **≥ 22.13**（本项目用内置 `node:sqlite`，故不再需要编译原生模块；
  实测环境为 Node 26）
- pnpm（工作区根目录）
- LM Studio 桌面版 + 官方 CLI `lms.exe`（通常在 `%USERPROFILE%\.lmstudio\bin`）。
  本服务不下载模型；它只用 CLI 启停**本地服务器**，不会打开图形界面，
  也不会终止 LM Studio 进程。

## 安装

```powershell
pnpm install
pnpm build            # 共享契约 -> 前端产物 -> 后端
```

`pnpm-workspace.yaml` 里用 `allowBuilds` 放行了 `esbuild` 的安装脚本（pnpm 12 默认拦截
依赖的安装脚本）。若换机器后 `pnpm install` 报 `ERR_PNPM_IGNORED_BUILDS`，按提示运行
`pnpm approve-builds` 即可。若安装时报
`thread '<unknown>' has overflowed its stack` 或仓库内校验锁文件供应链接连失败，
可用 `pnpm install --trust-lockfile` 跳过锁文件的供应链策略校验（本机验证过的方式）。

## 启动

最省事的方式（推荐）：在仓库根目录**双击 `run.cmd`**，或在 PowerShell 里执行

```powershell
.\run.ps1
```

脚本会自动完成：环境自检 → 首次运行装依赖 → 源码有改动就构建 → 检查端口 →
在独立窗口启动后端 → 等服务就绪 → **等待各子系统状态落定**（后端自动拉起
LM Studio 服务器并加载模型，最多重试 3 次，失败会在这里提示）→ 打开浏览器。
再次运行时会跳过构建，并在服务已在运行时直接给出界面地址。

> LM Studio 的启动与模型加载都归后端所有：端点不可达时它执行 `lms server start`
> （对「LM Studio 完全没开」的冷机器同样有效），随后运行"确保模型就绪"循环——
> 验证 + 重试最多 3 次，进度与结果由 `GET /api/service/status` 汇报（见下方
> 「模型加载失败会怎样」）。run.ps1 只负责把结论呈现给你，不参与加载。

可选参数：

```powershell
.\run.ps1 -Port 5175       # 换端口
.\run.ps1 -NoBrowser       # 不开浏览器
.\run.ps1 -Model <id>      # 换模型（透传给后端；默认 hy-mt2-30b-a3b-uncensored-v1-apex）
.\run.ps1 -SkipBuild       # 跳过构建检查（更快）
.\run.ps1 -ForceBuild      # 强制重新构建
```

**停止服务**：在界面上点「关闭服务」。它会卸载已驻留的模型以释放内存，然后关库退出；
**LM Studio 服务器会继续运行**（见下方「关闭服务到底做了什么」）。

也可以在后端窗口按 `Ctrl+C` 快速停止，但**结果不同**：它不会卸载模型，模型会继续占着
显存直到 LM Studio 的空闲自动卸载（最长约 1 小时），而且窗口会停在
`Terminate batch job (Y/N)?` 提示上，需要输 `Y` 或关闭窗口才彻底清理。
**历史数据不会受影响。** 详见下文「三种停止方式的区别」。

> ⚠️ 直接点后端窗口的 **X** 关闭按钮**不会**触发上述流程：它不送达可捕获信号，
> 模型不会被卸载、数据库不会正常关闭。兜底是 LM Studio 自带的空闲自动卸载
> （约 1 小时），所以最坏情况是模型多占一会儿内存。

## 程序化启动与关闭（供其它项目调用）

若由别的项目调度本服务，用下面两个脚本，全程**不需要知道后端 PID**：

```powershell
# 启动（-NoBrowser 必须带，否则会弹浏览器）
pwsh -File run.ps1 -NoBrowser -Port 5197

# 就绪判定：轮询到 200 才可以认为启动完成
#   GET http://127.0.0.1:5197/api/collections

# 关闭（幂等；返回 0 即表示模型已卸载、后端已退出）
pwsh -File shutdown.ps1 -Port 5197
```

`shutdown.ps1` 的两步是刻意的：

1. `POST /api/shutdown` —— 响应**只表示"已受理"**；
2. 轮询 `GET /api/collections` 直到连接被拒 —— 这才算真正结束。

卸载模型要几秒（实测约 2.4 秒）。**在第 1 步之后就动手关窗口或杀进程，会把卸载砍掉**，
模型将继续占着显存，停机也就失去意义。

`shutdown.ps1` 不会终止任何进程。后端跑在 `run.ps1` 开的一个可见控制台窗口里，
服务正常退出时该窗口会**自行关闭**——所以不需要 PID，也不需要额外清理。

> 偶尔（约 7 次里有 1 次）`pnpm` / `cmd` 那几层不会跟着退出，窗口会留在那里。
> 这不影响端口和服务（后端进程本身已经正常退出了），直接关掉那个窗口即可；
> `shutdown.ps1` 按设计不碰任何进程，不会代劳。

> 无人值守环境下注意：这个窗口会一直挂到服务退出为止。`run.ps1` 没有隐藏窗口的开关，
> 这是有意保留的（可见窗口便于看日志和排查）。要在后台跑，确保带 `-NoBrowser`，
> 并且**用 `shutdown.ps1` 或界面「关闭服务」停服务**——关窗口或按 `Ctrl+C` 都会跳过模型卸载。

注意：源码有改动时 `run.ps1` 会先构建，轮询就绪的超时值要留够。

## 手动启动（等价命令）

```powershell
pnpm install          # 首次
pnpm build            # 共享契约 → 前端产物 → 后端
pnpm start            # 运行 apps/server/dist
```

启动后访问 **http://127.0.0.1:5174** 。

开发模式（前端热更新）：

```powershell
pnpm --filter @ots/server dev     # 后端（5174）
pnpm --filter @ots/web dev        # Vite（5173），/api 代理到 5174
```

启动顺序（`DESIGN.md` §3.3）：

1. 初始化数据库（首次启动自动创建"默认合集"并设为当前合集）。
2. 探测 `LMSTUDIO_BASE_URL`：可达则直接使用；否则定位并启动 LM Studio，最多等待
   `LMSTUDIO_STARTUP_TIMEOUT_MS`。
3. 启动 HTTP 服务并托管前端。

> 服务只监听回环地址，且**没有鉴权**（按设计单机单人使用）。不要改 `HOST` 把它暴露到
> 局域网。

## 配置

全部通过环境变量，默认值见 `DESIGN.md` §11。最常用的几个：

| 变量 | 默认 | 用途 |
| --- | --- | --- |
| `PORT` | `5174` | 后端端口 |
| `LMSTUDIO_BASE_URL` | `http://127.0.0.1:1234` | 推理端点 |
| `LMSTUDIO_EXE` | 自动定位 | 手动指定 `lms.exe` / `LM Studio.exe` |
| `LMSTUDIO_MODEL` | `hy-mt2-30b-a3b-uncensored-v1-apex` | **本项目固定使用的模型 id**，加载/预热/卸载都以它为准。换模型改这一处即可 |
| `LMSTUDIO_AUTOSTART` | `true` | 置 `false` 则只使用已在运行的 LM Studio |
| `LMSTUDIO_WARMUP` | `true` | 就绪后是否显式预加载模型 |
| `TRANSLATE_MAX_CHARS` | `10000` | 单次翻译原文长度上限 |
| `DB_PATH` | `apps/server/data/translations.db` | 历史数据库文件 |

## 日常使用

界面会**记住你的选择**（存在浏览器本地，换浏览器或清空浏览器数据后会回到默认）：

- **翻译方向**（中→英 / 英→中）：下次打开还是上次的方向；
- **历史每页条数**（20 / 50 / 100 / 200）：在"翻译历史"标题右侧切换，会一直沿用；
- **上次选中的合集**：后端本来就把当前合集记在数据库里；如果它在别处被切换过，本页面
  也会回到你上次选中的那个（该合集已被删除时自动忽略）。

原文、译文和历史记录**不会**存在浏览器本地——它们要么是你正在编辑的内容，要么已经在
后端数据库里。

- **合集**：左栏新建、切换、重命名、删除。删除合集会级联删除其下所有历史；删掉当前合集
  会自动切到最近使用的合集（没有则新建"默认合集"）。
- **翻译**：右栏上方选择方向（中→英 / 英→中），输入原文，点"翻译"（或 `Ctrl+Enter`）。
  译文会流式显示在**输入框下方的"译文"输出框**里，完成后保留，可点"复制"取走；点"清空"
  只清空输出框，不影响已保存的历史。同一个合集同一时刻只允许一个翻译在跑。
- **多选删除**：
  - 勾选框 = 只选中该行；
  - 普通点行 = 只选中该行；
  - `Ctrl+点击` = 切换该行（不连续多选）；
  - `Shift+点击` = 从锚点行到该行整段选中；
  - 表头勾选框 / 列表聚焦时 `Ctrl+A` = 全选当前页；`Delete` = 批量删除。
  - 删除前会二次确认。
- **同一个合集同一时刻只能有一个翻译在跑**：翻译进行中"翻译"按钮与方向切换会禁用；不同
  合集可以同时翻译。
- **关闭**：
  - 「卸载模型」：只卸载 `LMSTUDIO_MODEL` 指向的模型（含它的全部实例），释放内存；
    **后端和 LM Studio 服务器都继续运行**，可以接着浏览历史。下次翻译会自动重新加载。
    只卸载这一个模型，不会动你为其它用途加载的模型。
  - 「关闭服务」：卸载模型 → 停止接受新连接 → 关数据库 → 退出。**不会**终止
    LM Studio，服务器留着继续运行。
  - 后端窗口按 `Ctrl+C`：能停服务，但**不卸载模型**，且窗口会停在
    `Terminate batch job (Y/N)?` 需手工确认。见下方「三种停止方式的区别」。
  - 直接点后端窗口的 **X**：见上文警告，什么都不会发生。

## 三种停止方式的区别

| 方式 | 停服务 | 卸载模型 | 清理窗口 | 历史数据 |
|---|---|---|---|---|
| 界面「关闭服务」／`shutdown.ps1` | ✅ | ✅ | ✅ 通常自动，偶有残留需手关 | 不受影响 |
| 窗口按 `Ctrl+C` | ✅ | ❌ 模型继续驻留 | ⚠️ 需输 `Y` 或关窗口 | 不受影响 |
| 窗口按 **X** | ✅ | ❌ | ✅ 随进程关闭 | 不受影响 |

**模型不卸载会怎样**：显存一直被占着，直到 LM Studio 自己判断空闲后自动卸载
（实测约 1 小时倒计时）。所以 `Ctrl+C` 之后马上要再翻译，模型还得重新加载一次（多等几秒）。

**为什么 `Ctrl+C` 不卸载**：`run.ps1` 通过 `pnpm.cmd start` 启动后端，中间有五层
子进程。按 `Ctrl+C` 时这个信号是**广播给整个控制台**的，`cmd.exe` 会拦截批处理并
终止整棵子进程树，后端进程在自己的卸载逻辑跑完之前就被连带杀掉了（实测 3–6 毫秒）。
直接在终端里跑 `node apps/server/dist/index.js` 就没有这层问题，但那样就没有
`Ctrl+C` 的便利了。

**历史数据为什么不受影响**：数据库用 WAL 模式，已提交的写入即使进程被强杀也不会丢；
实测 `taskkill /F` 硬杀后重开，条目数与内容完全一致。而且翻译记录只在流式完成的
`done` 事件时才写入，不会留下「写了一半」的记录。

> 程序化控制（由其它项目调度）**只能用 `shutdown.ps1`**：`Ctrl+C` 依赖有人在窗口前
> 手工确认，无法无人值守。

## 模型加载失败会怎样

启动时后端会后台运行「确保模型就绪」循环（DESIGN.md §6.3）：拉起 LM Studio 服务器、
加载 `LMSTUDIO_MODEL` 指向的模型，**失败会重试，共 3 次**（间隔约 10 秒）。

- **加载成功**：`run.ps1` 会打印「LM Studio 与模型就绪」。
- **3 次都失败**：**服务照常运行**——合集、历史等其它功能不受影响，只有翻译不可用
  （界面会显示 `LMSTUDIO_UNAVAILABLE`，可点「重试」）。`run.ps1` 会把失败原因
  打印出来，并提示「可能需要手动杀掉 LM Studio 进程后重试」。
- **统一状态端点**：`GET /api/service/status` 汇报 db / storage / lmstudio 三个模块
  的当前状态（`loading` / `ok` / `error`）。它不局限于模型——数据库、数据目录
  可写等非致命问题也会如实反映。程序化调用方可轮询它直到 `pending=false`
  （所有模块落定），再根据 `errors` 决定如何处理。
- **门户上报（Service alerts）**：如果 `run.ps1` 是被 personal-util-server 门户通过
  `startScript` 启动的，会拿到门户注入的 `PU_REPORT_URL` / `PU_REPORT_TOKEN`；
  启动失败时按门户协议把原因上报（POST `{token, message}` 到 `PU_REPORT_URL`），
  手机上的门户首页 / 管理页就能直接看到「离线翻译服务启动异常」及原因。
  手动运行（没有这两个环境变量）时跳过上报，只打印。

「可能需要杀 LM Studio」的意思是：LM Studio 偶发卡死在半加载状态时，杀掉它的进程
再让 `run.ps1` 重来，通常就能恢复。这只在确认 LM Studio 自身异常时才需要做——本服务
自己**从不**终止 LM Studio 进程（§6.4）。

## 关闭服务到底做了什么

顺序是固定的，每一步都可失败且**失败都不影响后续**：

1. **卸载模型** — `lms unload <LMSTUDIO_MODEL>`，逐个处理它的所有实例。
2. **复核** — 再查一次 `lms ps --json`，确认目标确实不再驻留。
   这一步不能省：`lms unload` 的退出码**恒为 0**（模型本来就没驻留时它也返回 0），
   只有列表能说明真相。若复核发现仍有驻留，界面会明确提示内存**没有**被释放。
3. **停止接受新连接** — 之后不再接受新请求，正在传输的流式翻译会被切断。
4. **关闭数据库** — SQLite 正常落盘退出。
5. 等约 150 毫秒让 HTTP 响应发出，然后进程退出。

若第 1 步失败（找不到 `lms.exe`、`lms` 调用失败或超时），服务**仍然会正常关闭**，
只是模型留在内存里——此时会在日志和界面提示，可稍后手动卸载，或等 LM Studio 的
空闲自动卸载。**任何情况下都不会为了释放内存去终止 LM Studio 进程。**

## 排障

| 现象 | 处理 |
| --- | --- |
| 页面提示"前端尚未构建" | 运行 `pnpm build:web` 后刷新 |
| 翻译报 `LMSTUDIO_UNAVAILABLE` | 在状态栏点「重试」；仍失败则手动开 LM Studio 的本地服务器，并确认 `LMSTUDIO_BASE_URL` 的端口与它一致 |
| 启动日志"仅定位到 LM Studio 桌面版" | 桌面版没有 `lms` 子命令，本服务无法启停服务器。安装官方 CLI（`%USERPROFILE%\.lmstudio\bin\lms.exe`）或用 `LMSTUDIO_EXE` 指定 |
| 第一条翻译很慢（几十秒） | 模型冷加载。保持 `LMSTUDIO_WARMUP=true`，或在 LM Studio 里手动加载模型；也可调大 `LMSTUDIO_LOAD_TIMEOUT_MS` / 推理请求超时 |
| 报 `INPUT_TOO_LONG` | 原文超过 `TRANSLATE_MAX_CHARS`（默认 10000 字符）；调大该变量或分段翻译 |
| 报 `TRANSLATION_IN_FLIGHT` | 同一合集的翻译还没结束；等待或换一个合集 |
| 点「卸载模型」提示失败 | 看提示里的原因：多为找不到 `lms.exe` 或调用超时。可在 LM Studio 里手动卸载，或等它的空闲自动卸载 |
| 关闭服务后想继续用 | 后端已退出，重新 `pwsh -File run.ps1 -NoBrowser` |
| 端口 5174 被占用 | 改 `PORT`，或结束占用该端口的进程（先用 `netstat -ano -p tcp \| findstr :5174` 确认 PID，不要按进程名批量清理） |

## 数据与隐私

- 历史记录是私人内容，存放在 `apps/server/data/translations.db`（已被 `.gitignore` 忽略，
  连同 WAL 文件）。**不要提交它，也不要在 issue / 文档 / 测试里粘贴真实译文。**
- 默认不记录原文与译文，只记录状态码与规模。
- 想清空历史：在界面上删除条目或合集；数据库文件本身请勿在服务运行时手工删改。
